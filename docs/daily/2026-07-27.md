### Teste manual ao vivo com o Felipe (`npm run tauri dev`)
Bugs reportados e corrigidos nesta ordem:
1. Janela travada, nao movia, sempre no topo — permission `core:window:allow-start-dragging` faltando
   na capabilities ACL (Tauri v2 bloqueia `data-tauri-drag-region` sem ela, silenciosamente).
2. Hotkeys nao respondiam — registro em lote (`on_shortcuts`) abortava os 4 shortcuts se 1 colidisse
   com outro app. Reescrito pra registro individual (`register_one`), resiliente a colisao parcial.
3. Overlay (pill de transcricao ao vivo) comecava a mostrar "..." e parava de atualizar — `realtime_manager.py`
   mandava o texto acumulado desde o inicio da gravacao, que estourava a largura fixa da pill (CSS
   `text-overflow:ellipsis` truncava). Corrigido pra mandar so o trecho da fala atual.
4. Icone da tray "bolinha verde" feio + dois icones aparecendo — dois bugs distintos: (a) icones eram
   placeholders solidos (sem desenho), gerados novos via PIL com glyph de headset+mic; (b) tray duplicada
   porque `tauri.conf.json` declarava `trayIcon` E o codigo Rust criava outra via `TrayIconBuilder` —
   removida a declaracao do config.
5. Pedido de UX: botao pra abrir a pagina de API key de cada provedor direto do app (`shell:allow-open`
   + `@tauri-apps/plugin-shell`). Tambem moveu o seletor de backend (local vs API) da aba "API" pra aba
   "Geral", que estava escondido e confuso.
6. Discussao sobre login OAuth automatico com provedores de API — nao e viavel (provedores nao expoem
   esse fluxo pro publico); avaliado e descartado por ora, foco ficou no fluxo manual simplificado.

### Empacotamento Windows (MSI + NSIS)
- Renomeado app pra "Scribe4me v2" em toda a UI (productName, titulo da janela, tooltip da tray) —
  pedido explicito do Felipe pra nao confundir com o v1 (Python/tkinter) que tambem esta instalado.
- `sidecar/build_sidecar.bat` (PyInstaller) + `npm run tauri build` — gerou MSI (394MB) e NSIS (278MB).
- Bug critico no primeiro instalador: app crashava ao abrir ("Sidecar binary not found"). Causa:
  `bundle.resources` com glob `../sidecar/dist/...` fazia o Tauri preservar a pasta `../` como `_up_`
  literal no bundle, resultado nao batia com o path que o codigo Rust esperava. Corrigido com mapeamento
  explicito `{origem: destino}`.
- Apos o fix, app abriu mas Felipe reportou: PowerShell/console vazio abrindo junto, overlay sem texto
  as vezes, app fechando sozinho durante gravacao, 2 icones na taskbar ao gravar. Causa suspeita: o
  binario PyInstaller do sidecar e `console=True` (proposital pra debug) — em release, sem console
  proprio no processo pai, o Windows abre uma janela de console visivel pro filho (nao acontecia em dev,
  onde o console e herdado do terminal). Fix: `CREATE_NO_WINDOW` no spawn (`sidecar.rs`).
- Rebuild feito, instalador relancado — **sessao encerrou antes da confirmacao do Felipe** se esse fix
  resolveu os 4 sintomas.
